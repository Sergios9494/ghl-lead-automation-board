## Core premise

AI has moved past code generation. Security researchers are building AI agents
that assist with **vulnerability discovery**, **HTTP traffic analysis**, and
**security report generation**.

The framing that makes it work: **train the agent like a junior pentester.**
Teach it through curated security research, technical documentation, and
reusable pentesting skills — rather than relying on raw model capability plus
generic instructions.

> Key idea: a well-designed methodology makes an AI agent more useful than a
> stronger model working from generic instructions alone.

## The four pillars of the methodology

### 1. Security Skills
Structured, reusable knowledge packaged per vulnerability class and per testing
workflow. Each skill encodes how a researcher actually approaches that bug class
— the preconditions, the probe sequence, the signals that distinguish a real
finding from noise.

### 2. Specialized Agents
Separate agent roles rather than one monolithic agent. Critically, a dedicated
**validation agent** whose job is confirming findings and **driving down false
positives** — the single biggest failure mode of automated scanning.

### 3. Tool Integration
Wire the agent into real security tooling instead of having it reason in the
abstract:
- **Caido** — HTTP proxy / web traffic interception and replay
- **Ghidra-style workflows** — binary and reverse-engineering analysis
- Claude Code as the agent runtime / orchestration layer

### 4. Reusable Knowledge
Persist findings and techniques back into the skill library so each engagement
improves the next one. The agent compounds instead of starting cold every time.

## Safety / scope constraints (non-negotiable)

Autonomous security testing can cause unintended damage. From the source, and
worth treating as hard rules:

- **Authorized scope only.** Test only what you have written authorization for.
- **Isolated environments** where appropriate — don't let an autonomous loop
  run against production you don't own.
- **Human approval retained for sensitive actions.** The agent proposes;
  a human authorizes anything destructive, lateral, or externally visible.
- Validation-before-report is a safety control, not just a quality one — an
  unvalidated autogenerated finding wastes defender time and erodes trust.

## Why this matters for our work

The shift is not "AI writes exploit scripts." It's **AI learning how security
researchers work** — encoding methodology, not just capability. Practical
implications:

- Our own pentesting workflows are candidates for skill-ification (repeatable
  recon, auth/authz testing, traffic analysis triage).
- False-positive suppression via a separate validator agent is the design
  pattern most worth copying first.
- It also defines a **threat model**: the same methodology is available to
  adversaries, so expect faster, cheaper, more methodical automated attacks.

## Related intel from the same source (AI category)

- **VulnHunter** (Oct 28, 2026) — self-hosted AI security workbench that finds
  vulnerabilities, generates PoC exploits, and helps verify findings in one
  platform.
- **Node2Shell / CVE-2026-111497** (Oct 23, 2026) — OpenAI Codex Security
  assisted researchers in finding a high-severity Node.js RCE reachable via
  malicious Brotli data. Example of AI-assisted discovery landing a real CVE.
- **"The Malware With No Code"** (Oct 22, 2026) — VirusTotal found thousands of
  malicious AI agent skills containing **no malicious code at all**; the payload
  is plain-language instructions that scanners never flag. Directly relevant: if
  we build a skill library, the skill files themselves are an attack surface.
  Treat third-party skills as untrusted input and review them by hand.
